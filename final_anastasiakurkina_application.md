**[ НАЗВАНИЕ ПРОЕКТА ]**

“HappyHome”

**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

Отсутствие единой и доступной всем членам семьи базы лекарств с указанием их срока годности и назначения. Несвоевременное пополнение домашней аптечки, из-за чего велик риск употребить просроченное лекарство в момент, когда оно очень нужно. Ежедневной рутиной каждой семьи является приобретение продуктов питания и товаров первой необходимости. Часто нужные продукты никем не куплены, зато приобретено что-то другое в избыточном количестве, и семейный бюджет тратится впустую. Из-за забывчивости и занятости члены семьи не соблюдают режим полива растений или путают периодичность полива для разных растений, в результате чего растения чахнут.

**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**

Целевая аудитория:

* Взрослые люди 30-40 лет, проживающие совместно с другими членами семьи и ведущие домашнее хозяйство, объединённые общими бытовыми вопросами.

**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]**

Стек (фактически реализованный):

* **Мобильное приложение (клиент):** React Native + Expo (expo-router), TypeScript. Состояние: Zustand (токен сохраняется на устройстве через AsyncStorage, пользователь), запросы и кеш: TanStack React Query + Axios. Уведомления в интерфейсе: react-native-toast-message. Иллюстрации: SVG. Проект содержит нативную Android-часть (`mobile/android`, Expo prebuild, new architecture, Hermes), настроены Firebase (google-services, Crashlytics).
* **Сервер (бэкенд):** Node.js + Express 4, TypeScript. Авторизация: JWT (срок жизни токена 8 часов), хеширование паролей bcryptjs. Отправка писем верификации: Nodemailer (Gmail SMTP). Валидация входных данных на сервере, ограничение частоты запросов к `/auth`, тесты на встроенном `node:test`.
* **База данных:** MongoDB (Mongoose 7).
* **Развёртывание:** Docker / docker-compose (контейнеры `app` и `db` с образом `mongo`), production-образ `server/Dockerfile.prod`; CI/CD на GitHub Actions: проверка типов и тесты на каждый push/PR, сборка образа в GHCR и автоматический деплой на сервер по SSH.

Первая версия приложения ориентирована на Android (applicationId `ru.anasty.HappyHome`).

* Android – (Android 7) и выше.

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**

Приложение для личного/семейного использования. Не предназначено для крупных бизнесов или больших сообществ. Цифровой продукт, распространяемый через магазины приложений.

**Реализовано:**

* **Авторизация.** Регистрация по email и паролю (минимум 6 символов), отправка письма со ссылкой верификации, выход из аккаунта. После регистрации и при входе неподтверждённого пользователя показывается экран «Подтвердите почту»: кнопка «Я подтвердил почту», автоматическая проверка каждые 5 секунд и повторная отправка письма (не чаще раза в минуту). Доступ к данным открывается только после подтверждения. Токен хранится на устройстве, при истечении срока пользователь возвращается на экран входа.
* **Профиль.** Просмотр email, редактирование имени (инициалы в аватаре формируются автоматически).
* **Семья.** Создание семьи (владельцем становится создатель), присоединение к существующей семье по идентификатору, возможность поделиться идентификатором через системное меню «Поделиться», выход из семьи. Данные модулей общие для всех участников семьи. Список участников доступен через API; при выходе владельца владение переходит другому участнику, а когда выходит последний участник, семья и её данные удаляются.
* **Модуль 1. Умная аптечка.**
  * Добавление, редактирование и удаление лекарства (название, назначение, срок годности, количество).
  * Автоматический статус по сроку годности: «В порядке», «Истекает скоро» (≤ 30 дней), «Просрочено»; цветовая индикация, счётчик оставшихся дней.
  * Фильтрация по статусу (все / просрочено / истекает / в порядке) и сортировка (по сроку, названию, статусу).
  * Подтверждение удаления в анимированном диалоге.
* **Модуль 3. Список покупок.**
  * Добавление, редактирование и удаление покупки (название, категория, количество, срок «купить до», периодичность: разово / раз в неделю / раз в 2 недели / раз в месяц).
  * Отметка «Куплено»: для повторяющихся покупок сервер автоматически создаёт следующую с новым сроком.
  * Статусы «Ожидает», «Просрочено», «Куплено», сортировка (по сроку, названию, категории, статусу), переключатель показа купленных.
* **Помощь.** В профиле есть раздел «Помощь» с описанием всех действий пользователя.
* **Модуль 2. Уход за растениями.**
  * Картотека растений: название, особенности ухода, частота полива (каждый день / 2 дня / 3 дня / неделя / 2 недели / месяц).
  * Автоматический расчёт статуса полива («Полив не нужен», «Полить сегодня», «Полив просрочен») и количества дней до следующего полива; сортировка по близости полива.
  * Отметка о поливе с подтверждением, ведение истории ухода (дата, время, примечание).
  * Просмотр истории полива в отдельном окне.

**Не реализовано / запланировано:**

* Push-уведомления (об окончании срока годности, о поливе).
* Роли и права участников семьи (сейчас все участники равноправны).
* Фото растений и лекарств.

**API сервера** (префикс `/api`, токен передаётся в заголовке `Authorization`):

| Маршрут | Метод | Назначение |
|---|---|---|
| `/auth/register` | POST | регистрация, отправка письма верификации |
| `/auth/verify/:token` | GET | подтверждение почты |
| `/auth/login` | POST | вход, выдача JWT |
| `/auth/resend` | POST | повторная отправка письма верификации |
| `/user` | GET | профиль текущего пользователя |
| `/user/update` | PUT | изменение имени / присоединение к семье |
| `/user/leave-family` | DELETE | выход из семьи |
| `/family/create` | POST | создание семьи |
| `/family?id=` | GET | получение своей семьи |
| `/family/members` | GET | участники семьи |
| `/pill`, `/pill/create`, `/pill/update`, `/pill/:id` | GET / POST / POST / DELETE | аптечка |
| `/plant`, `/plant/create`, `/plant/:id`, `/plant/:id/care`, `/plant/:id` | GET / POST / PUT / PUT / DELETE | растения, полив |
| `/shopping`, `/shopping/create`, `/shopping/:id`, `/shopping/:id/bought`, `/shopping/:id` | GET / POST / PUT / PUT / DELETE | покупки |

**Модели данных (MongoDB):**

* `User` — email, password (хеш), name, family_id, isVerified, emailToken.
* `Family` — name, owner_id.
* `Pill` — name, description, expiresAt, quantity, createdAt, createdBy, family_id.
* `Plant` — name, description, waterFrequency, lastWateredAt, createdAt, createdBy, family_id, careHistory[] (вложенные записи: note, createdAt, createdBy).
* `Shopping` — name, category, quantity, buyByDate, frequency, bought, boughtAt, createdAt, createdBy, family_id.

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

1) Группа приложений для отслеживания геолокации и местоположения телефона ребёнка. Не решают проблему ведения базы покупок и мониторинга выполнения нужных задач в кругу семьи.
2) Совместный календарь с некоторыми дополнительными функциями (фотоальбом, книга семейных рецептов и т.д.).
3) Приложения-помощники в рутинных делах, но зачастую проект решает одну задачу (например, планирование семейного бюджета), нужно ставить несколько приложений, что занимает место на телефоне, а пользователь вынужден переключаться между ними.

Анализ 3 программных продуктов, максимально приближённых к заданному функционалу:

* Cozi Family Organizer – содержит календарь-синхронизатор для всей семьи, но нет умного автодобавления рутинных действий, а также отсутствует умная аптечка.
* PikaPika – позволяет назначить список задач и ответственных за их выполнение, решает задачу делегирования обязанностей.
* Trello – набор функций на основе карточек, досок задач, команд. Не позволяет отслеживать состояние домашней аптечки, создавать по расписанию задания на приобретение товаров первой необходимости, бесплатная версия ограничена по функционалу.

**[ ОБОСНОВАНИЕ ВЫБОРА ИНСТРУМЕНТОВ ]**

* **React Native + Expo.** Один код на TypeScript для Android и iOS; не нужно отдельно изучать нативную разработку, быстрый цикл отладки на устройстве. Сначала планировался Kotlin, но срок проекта не позволял освоить новый язык и платформу.
* **TypeScript на клиенте и сервере.** Общий язык и общие типы данных (DTO) уменьшают число ошибок на стыке клиента и сервера.
* **Express.** Минимальный фреймворк: для REST API с десятком маршрутов не нужна тяжёлая инфраструктура.
* **MongoDB + Mongoose.** Документы естественно описывают сущности с вложенными данными (история ухода за растением хранится внутри записи растения), схемы Mongoose дают валидацию и типы.
* **TanStack React Query + Zustand.** React Query берёт на себя загрузку, кэш и обновление списков, Zustand хранит только токен и пользователя; вместе это заметно проще Redux.
* **JWT + bcryptjs.** Сервер не хранит сессии, а пароли хранятся только в виде хеша.
* **Docker и GitHub Actions.** Одинаковое окружение на разных машинах и автоматическая проверка и выкладка при каждом изменении.
